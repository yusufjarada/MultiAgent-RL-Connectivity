What you're looking at

A team of agents is trying to spread out and cover a set of target positions. Each agent can only see its own local surroundings, so to coordinate they need to communicate. But communication isn't free — agents have a limited radio range, and in real systems (drone swarms, robot teams, autonomous vehicles) bandwidth is expensive. The question is: can agents learn to communicate efficiently without losing the ability to coordinate?

The three communication strategies

Broadcast (CommNet)

Every agent sends a message to every other agent within range, at every timestep. Simple and effective for small teams, but the number of messages grows quadratically — 10 agents means 45 links, 50 agents means 1,225. Most of these messages carry redundant information. This is the baseline: it works, but it doesn't scale.

Gated (IC3Net)

Each agent has a learned gate that decides whether to transmit at each timestep. If an agent has nothing useful to say, it stays silent. This cuts down on communication, but there's a catch: if too many agents go quiet at the same time, the team can split into disconnected groups. When the Fiedler value (the number in the sidebar) drops to zero, at least one agent has no path to reach another — the team has lost coordination.

Gated + Connectivity Constraint (Ours)

Same gating idea, but with a mathematical safety net. Before an edge is dropped, the system checks the algebraic connectivity of the communication graph (the Fiedler value). If removing an edge would disconnect the team or push connectivity too low, that edge stays open. Agents still learn to be efficient — they shut off unnecessary links — but the team is guaranteed to stay connected. This is the core contribution: combining learned communication efficiency with provable connectivity guarantees from graph theory.

What's the Fiedler value?

It's the second-smallest eigenvalue of the graph Laplacian — a single number that measures how well-connected a network is. If it's zero, the graph is disconnected (some agents can't reach others through any chain of links). The higher it is, the more robust the connectivity. Our method keeps this value above a threshold while still allowing agents to reduce unnecessary communication.

Where this matters

Drone swarms — Search-and-rescue or surveillance missions where UAVs need to coordinate coverage while operating on limited radio bandwidth.
Warehouse robotics — Hundreds of robots picking and moving items need to share routing information without flooding the network.
Autonomous vehicles — Cars at an intersection sharing intent (turning, braking) with nearby vehicles under strict latency and bandwidth constraints.
Multi-robot exploration — Robots mapping an unknown environment need to stay coordinated even as they spread out and some links drop due to distance or obstacles.

About this demo

The agents here are following a simple attraction rule toward their target positions — they aren't running a trained neural network. The gating behavior is simulated with oscillating functions to approximate what a learned gate would do. The actual training pipeline uses PyTorch with multi-agent reinforcement learning (MARL) on cooperative benchmarks. This demo exists to build intuition about why connectivity-constrained communication matters before looking at training results.
